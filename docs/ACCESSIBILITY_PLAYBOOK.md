# ACCESSIBILITY PLAYBOOK (시각장애인 접근성 스토리보드 정의서)

본 문서는 시각장애를 가진 유저(전맹 및 저시력자)가 화면을 보지 않고도 스마트폰의 오디오 안내(TTS), 스크린 리더(TalkBack/VoiceOver), 특화 햅틱(진동) 패턴, 그리고 무장벽 제스처 제어만을 이용해 "나야~ 영어" 플랫폼의 전 기능을 완벽하게 누릴 수 있도록 설계된 **시각장애인 접근성(A11y) 스토리보드 및 연계 검증서**입니다.

---

## 1. 시각장애인 페르소나 정의
- **사용자**: 이민우 (25세, 대학생, 시각장애 1급 전맹)
- **보조도구**: Android TalkBack 활성화 상태 + 스마트워치 착용
- **목표**: 안내인의 도움 없이 스마트폰의 소리만을 이용하여 매일 영어를 암기하고 주말 대화를 이행함.
- **아키텍처적 특성**: "나야~ 영어"는 **오디오 재생(TTS)과 마이크 발화(STT)가 중심인 서비스**이므로, 접근성 UX만 올바르게 설계되면 시각장애인에게 가장 최적화된 학습 앱이 될 수 있습니다.

---

## 2. 시각장애인 특화 핵심 UX 스토리보드 (Accessibility Scenes)

### 🎬 SCENE A: 틈새 좀비 노출 시 스크린 리더 및 사운드 비컨 (Screen Reader Alert)
화장실 앉기 등 틈새 시간이 감지되어 좀비 팝업이 활성화되었을 때, 시각적으로 볼 수 없는 이민우 유저를 위한 청각적/햅틱 피드백 단계입니다.

#### 🔊 스크린 리더 안내 명세 (TalkBack / VoiceOver Output)
```
[ 햅틱 피드백: "두 번 연속 강한 진동 진동 (드르륵-드르륵)" 발생 ]
[ 사운드 비컨: 소프트 차임 벨소리 송출 ]
TalkBack 음성 안내:
"나야 영어, 틈새 좀비 학습이 활성화되었습니다. 
오늘의 단어를 들려드립니다. 
표현: Take it easy. 
뜻: 진정해, 마음을 편하게 먹다. 
화면 아무 곳이나 두 번 두드리면 연인 보이스로 실제 예문을 재생합니다. 
오른쪽으로 쓸어넘기면 화면이 닫힙니다."
```
- **디바이스 간 연계 흐름**:
  1. 기기가 틈새 유휴 상태(화장실 착석)를 감지하여 백그라운드에서 깨어남.
  2. 스크린 리더 감지 API가 작동하여 **'접근성 모드 활성 상태'**임을 감지.
  3. 화면의 가시적 팝업을 띄움과 동시에, 시각장애인이 인지할 수 있는 특유의 **'사운드 비컨(알림용 벨소리)'**과 **'고유 진동 패턴(2연타 강한 햅틱)'**을 발산함.
  4. 단어와 뜻을 TalkBack이 자동으로 낭독하며, 화면 전체 영역이 하나의 거대한 '더블 탭 재생 버튼'으로 활성화됨.

---

### 🎬 SCENE B: 노룩 제스처 저녁 12문항 퀴즈 (No-Look Gesture Quiz)
화면의 텍스트 버튼 위치를 보면서 누르기 힘든 전맹 유저를 위해 **오직 제스처와 소리만으로 정답을 스위칭하고 선택하는 특화 퀴즈 인터페이스**입니다.

#### 📱 노룩 제스처 UI 동작 메커니즘 (Gesture Layout)
```
+--------------------------------------------------------+
| [10:00 PM]                    [NO-LOOK GESTURE QUIZ]   |
|                                                        |
|   ==================================================   |
|   |             [ 화면 전체 영역 ]                 |   |
|   |                                                |   |
|   |   - 왼쪽으로 쓸어넘기기 (Swipe Left):           |   |
|   |     "이전 선택지 듣기"                         |   |
|   |                                                |   |
|   |   - 오른쪽으로 쓸어넘기기 (Swipe Right):       |   |
|   |     "다음 선택지 듣기"                         |   |
|   |                                                |   |
|   |   - 아래로 쓸어넘기기 (Swipe Down):            |   |
|   |     "현재 문제 질문 다시 듣기"                 |   |
|   |                                                |   |
|   |   - 화면 전체 어디든 더블 탭 (Double Tap):       |   |
|   |     "현재 들려주는 선택지 정답으로 확정!"       |   |
|   |                                                |   |
|   ==================================================   |
|                                                        |
|   [채점 피드백]                                        |
|   - 정답 시: 경쾌한 '딩동댕' 차임 + 부드러운 잔떨림 햅틱 |
|   - 오답 시: 묵직한 '웅-' 베이스음 + 강한 1회 끊김 햅틱   |
+--------------------------------------------------------+
```
- **제스처 기반 퀴즈 플레이 흐름**:
  1. 밤 10시 정각 알람이 울리고 유저가 화면을 두 번 탭하여 퀴즈방 진입.
  2. 시스템이 문제를 읽어줌: *"Question 1. Take it easy의 알맞은 의미는?"*
  3. 유저가 오른쪽으로 쓸어넘김(Swipe Right) -> *"1번 보기. 쉽게 가져가다."*
  4. 유저가 오른쪽으로 쓸어넘김 -> *"2번 보기. 진정하고 마음을 편하게 먹다."*
  5. 원하는 정답을 인지한 유저가 **화면 어디든 빠르게 두 번 탭(Double Tap)함**.
  6. 채점 결과 정답 판정. 다정한 보조 오디오 효과와 함께 2번 문제로 자동 갱신.

### 🎬 SCENE C: 핸즈프리 음성 감지 대화방 (Hands-Free AI Chat)
미세한 터치가 어려운 시각장애인을 위해 마이크 단추를 조준해 터치할 필요가 없는 **완전 무장벽 대화(Hands-Free Speech View)**를 제공합니다.

#### 🎙️ Voice Activity Detection (음성 활성 감지) 기반 대화 흐름
```
[대화방 입장] ---> (TTS: "버디가 대화 대기 상태입니다. 말씀하십시오.")
                       |
                       v
[유저가 마이크 조준 없이 바로 영어 발화] (예: "I feel sick today.")
                       |
                       v (폰 자체 VAD 알고리즘이 유저의 말하기 시작과 끝을 주파수로 자동 분석)
[말끝 정지 감지 1.2초 후 자동으로 STT 변환 송출]
                       |
                       v
[AI 버디가 답변과 발음 팁 낭독] 
"Oh, sweetheart. I'm sorry to hear that. Next time, say 'I'm feeling sick today!' 
Are you under the weather?"
```
- **핸즈프리 연계 흐름**:
  1. 주말 실전 회화방 입장 시 TalkBack이 대기 상태임을 청각 고지.
  2. 화면의 마이크 버튼 조준 터치 필요 없이, 기기 마이크의 **음소 수집 엔진(VAD)**이 상시 대기.
  3. 유저가 영어를 말하기 시작하면 오디오 이퀄라이저 파동이 발생(워치 햅틱으로 유저에게 말하는 중임을 진동 고지).
  4. 유저의 발화가 끝나고 무음이 1.2초 지속되면 단말기가 알아서 녹음을 닫고 백엔드 API에 음성을 밀어 넣어 피드백 수신 및 TTS 재생.

## 3. 접근성 구현을 위한 OS 네이티브 기술 스펙 (Native A11y Specs)

### 🤖 Android TalkBack 지원을 위한 XML / Compose 속성
시각장애인 스크린 리더가 각 가상 컴포넌트의 성격과 값을 정확하게 해석하도록 돕는 네이티브 속성입니다.

```xml
<!-- Android XML Accessibility Label Binding -->
<ImageButton
    android:id="@+id/btn_speak_word"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:src="@drawable/ic_play"
    android:contentDescription="학습 단어 음성 듣기 버튼"
    android:accessibilityTraversalBefore="@+id/btn_zombie_ok" />
```

### 🍏 iOS VoiceOver 최적화 코드 (Swift)
```swift
// iOS UIKit VoiceOver Properties 구성
btnSpeakWord.isAccessibilityElement = true
btnSpeakWord.accessibilityLabel = "영어 예문 발음 재생 단추"
btnSpeakWord.accessibilityHint = "이중 탭하면 현재 선택된 페르소나 목소리로 단어와 예문 오디오를 들려줍니다."
btnSpeakWord.accessibilityTraits = .button
```

### 📳 접근성 특화 진동 피드백 구현 (Native Haptics)
단말기 진동 파형을 미세 조작하여 눈이 전혀 보이지 않는 유저에게 햅틱만으로 정보를 전달합니다.

```kotlin
// Android Haptic Vibrator 효과 생성 (정답과 오답 피드백 차별화)
val vibrator = context.getSystemService(Context.VIBRATOR_SERVICE) as Vibrator

if (isCorrectAnswer) {
    // 경쾌한 정답 리액션: 짧고 통통 튀는 진동 2회
    val correctEffect = VibrationEffect.createWaveform(
        longArrayOf(0, 80, 50, 80), // 대기, 진동, 대기, 진동 (밀리초)
        intArrayOf(0, 180, 0, 255), // 각 진동 세기 (0~255)
        -1
    )
    vibrator.vibrate(correctEffect)
} else {
    // 묵직한 오답 리액션: 낮고 길게 끄는 묵직한 진동 1회
    val wrongEffect = VibrationEffect.createOneShot(350, 100) // 350ms 동안 100 세기로 진동
    vibrator.vibrate(wrongEffect)
}
```

## 4. 접근성(A11y) 검증 항목 및 예외 시나리오 (Checklist)

### 🔍 1. 초기 온보딩 및 앱 시작 단계 무장벽 설계 (Audio-Guided Onboarding)
- **문제점**: 시각장애인 유저가 최초 앱을 다운로드한 직후, 초기 설정(이름 입력, 회원가입, 접근성 권한 승인)을 기기 리더 없이 스스로 헤쳐 나가기 불가능함.
- **해결책**:
  - 앱 첫 실행 감지 시 단말기 스크린 리더 여부와 상관없이 시스템 기본 TTS가 강제로 작동하여 **'오디오 가이드 가입 세션'**을 트리거합니다.
  - *"반갑습니다. 나야 영어 가입을 환영합니다. 화면 아무 곳이나 두 번 누르시면 본인의 스마트워치와 자동으로 연결성을 탐색합니다."* 와 같은 성우 톤 TTS 음성으로 가입부터 시작할 수 있도록 100% 보증합니다.

### 🔍 2. 소리 재생 음량 과적 제어 (Ear Safety Protection)
- **문제점**: 시각장애인은 이어폰을 항상 끼고 생활하는 경우가 많음. 좀비 모드 팝업이 활성화되면서 극도로 시끄러운 데시벨(dB)로 TTS 오디오가 재생되면 고막 손상의 위험이 큼.
- **해결책**:
  - 단말기 미디어 볼륨 수준을 동적 감지합니다.
  - 최대 볼륨의 70%가 넘어가는 세팅일 경우, 좀비 팝업 구동 시 강제로 미디어 볼륨을 **50% 수준으로 자동 감쇠(Ducking)** 시킨 뒤 부드러운 Fade-in 효과를 동반하여 음성을 송출함으로써 유저의 청각 안전을 극대화합니다.
